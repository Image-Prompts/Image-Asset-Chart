# Image Asset Chart · 人物三视图与海报库

仅收录人物三视图（含角色多视图设定）和提示词生成的海报。每人一个分册，所有图片共用一个总册。网页支持按姓名浏览、搜索、完整原图预览、下载和复制调用路径。

## 第一次使用：把这句话交给 Agent

> 请把 https://github.com/Image-Prompts/Image-Asset-Chart 克隆到本地，先阅读 AGENTS.md。我叫「你的姓名或昵称」，图片在「本地文件夹路径」。请逐张识别内容、按规则命名、建立我的分册、更新总册，然后启动网页给我看。需要上传共享时请帮助我提交上传，并一步步告诉我需要完成的登录操作。

替换姓名与路径，也可以直接把图片交给 Agent。已经有本地项目时让 Agent 在现有目录继续。无需自己学习 Git 或敲命令，Agent 应依次帮助你：

1. 首次启动，Agent 会先问“这次需要上传图片，还是先浏览已有图片？”只浏览就直接打开网页；已经明确要求上传时不重复问。
2. 需要上传时，确认你的姓名或昵称，并问图片叫什么；没有指定名称就由 Agent 看图命名。
3. Agent 新建 `incoming/你的名字/` 收图文件夹，告诉你完整路径。你只需要把图片放进去，再告诉它“放好了”。已有图片路径或附件时直接使用，不用重复放图。
4. Agent 继续看图命名，复制到 `assets/你的名字/`，更新总册和个人分册；收图文件夹保留原图且不提交。
5. 启动网页，检查左侧有你的名字，点击可见完整图片。
6. 选择上传即由 Agent 接着提交并推送，或创建 Pull Request；需要登录或没有权限时一步步说明具体操作。上传成功后其他朋友才能拉取到图片。

## 本地启动

需要 Node.js 20 或更高版本及 Git。没有第三方运行依赖，不需要安装依赖或构建。

```sh
git clone https://github.com/Image-Prompts/Image-Asset-Chart.git
cd Image-Asset-Chart
npm start
```

打开 <http://localhost:3000>，保持终端运行。按 `Ctrl+C` 停止；下次在项目目录执行 `npm start` 即可。端口占用时关闭旧服务，或设置环境变量 `PORT` 选择其他端口。

左侧“全部图片”展示总览，姓名进入个人分册。“图片墙 / 资产总册”切换查看方式。图片墙使用瀑布流，横图和竖图按原比例与自然高度完整显示，无背景色或底纹，图片之间保留少量间隔。点击图片可查看完整原图、下载或复制路径。搜索支持名称与成员姓名。新增文件后点击“刷新图片”，无需重启。

首次询问由 Agent 按规则执行；直接运行 `npm start` 会启动浏览服务。随时可点击网页“如何添加图片”查看收图步骤。

## 图片分类

图片墙提供「人物三视图」「提示词海报」两个标签，默认显示三视图。类别可与成员、搜索、排序及资产总册视图组合使用，标签数量反映当前成员和搜索条件下的图片数。

`asset-categories.json` 按图片相对路径登记类别：`three-view` 或 `poster`。新增图片时同步登记，再运行 `npm run catalog`；缺少类别时会提示对应路径。类别也会写入生成的 JSON 和 Markdown 总册。原图路径保持不变。

现有海报未收录提示词原文；「提示词海报」是图片分类，后续提供原文后可另行补充。

## 存储与命名规则

```text
assets/
  Fries/
    Fries__天使恶魔双生__001.png
    Fries__白衣月夜魔术师__001.png
  小缪/
    小缪__蓝裙女性角色设定__001.png
  小熊/
    小熊__黑帽小熊多视图__001.png
```

- **目录**：`assets/上传者姓名/`。每人固定使用一个姓名或昵称；个人“库 / 分册”就是此共享 Git 仓库内的文件夹，不用另外创建 GitHub 仓库。
- **文件名**：`姓名__图片名称__三位序号.原扩展名`。两个分隔符均为两个下划线，姓名必须与目录一致。
- **图片名称**：Agent 先看图，再用简短中文描述主体和显著的服装、动作或场景，如 `红衣王座肖像`。上传者和画面角色是两个概念；知道角色名时可写入图片名称，不知道就描述画面，不猜身份。
- **序号**：同一上传者、同一图片名称从 `001` 递增。不同主题各自从 `001` 开始。目标文件已存在则用下一个可用序号，不覆盖。
- **字符**：姓名和图片名称使用中文、英文字母、数字、单个短横线；不用空格、路径分隔符、双下划线。
- **格式**：PNG / JPG / JPEG / WebP / GIF / AVIF。扩展名小写且保持原图实际格式；改名不转码、不裁剪、不压缩。
- **层级**：图片直接放个人目录内，不再套子分类。第一阶段按成员分类，图片名称用于搜索。

## 总册和分册

| 文件 | 用途 |
| --- | --- |
| [CATALOG.md](CATALOG.md) | 全员总册：归属、图片名称、序号、可点击原图路径 |
| [catalog/](catalog/) | 每个人的 Markdown 分册 |
| [catalog.json](catalog.json) | Agent 结构化索引：名称、归属、路径、格式、大小 |
| `assets/姓名/` | 图片原文件，唯一事实来源 |

执行 `npm run catalog` 更新所有册子；启动服务与网页刷新也会自动更新。不要手改生成文件。图片和生成的册子一起提交。

Agent 调用示例：在 `catalog.json` 查找 `owner` 为 `Fries`、`name` 为 `天使恶魔双生` 的条目，读取 `path` 对应原图；路径相对于项目根目录，序号区分同主题图片。

## 分享与同步

本地可见不等于已共享。整理后可对 Agent 说：

> 请按 AGENTS.md 把这次图片和总册提交并上传；没有写权限时准备 Pull Request，并一步步告诉我需要完成的登录操作。

其他朋友让 Agent 更新本地仓库后刷新网页即可。没有写权限时通过 Fork 和 Pull Request 贡献，由维护者合并；不要强推或覆盖其他成员文件。

## 第一阶段范围

本地浏览、按姓名分类、识图命名、总册和分册、原图下载与路径调用。入库由 Agent 或本地文件操作完成。没有网页上传、账号系统、数据库或云存储。
